## 决定与理由

Android按已授权的普通远控连接管理画面接收资格。有开发者连接时暂停全部普通连接画面；多个开发者均可接收；最后一个开发者离开后恢复普通连接。注册发生在端点认证成功及有效登录响应之后、视频订阅之前，错误登录、文件/终端/隧道/摄像头会话不取得该角色。关闭与Drop幂等释放，网络异常以既有连接存活检测清理为准，不承诺瞬时检测进程崩溃。

暂停只过滤媒体分发，不停止MediaProjection、普通采集或ADB源，不移除普通会话，不修改ZEGO状态。普通连接继续状态、心跳、邀请、接听、拒绝、挂断和现有双向语音；原单通话忙规则保持。恢复只刷新既有正常视频并等待ADB关键帧，不触发Android屏幕授权或自动切无视。

普通连接暂停期间同时阻止盲输入、采集控制、截图和ADB变更；状态查询/订阅/ACK及语音保留。暂停释放该连接的ADB触摸与待处理剪贴板同步，不释放其他连接的输入资源。用户已通过异步问题明确选择“同时暂停操作，保留语音”，确认此规则。

## 资格与兼容边界

本地密码验证成功后通过手写C ABI `openworld_enable_developer_mode()`设置Rust进程内原子标志，desktop各Flutter engine共享；不持久化，重启复位。新建/重连的普通会话发送`LoginRequest.developer_mode = 17`；已连接会话不热升级，提示重连。

这是官方客户端之间的协作策略，角色位不是签名凭证。修改版已授权客户端可以伪造角色；本地密码不传输，不替代端点认证，SEC-016仍开放。如需抗伪造，必须另行设计可信签发者、期限、撤销和设备绑定，不能由本轮虚构仓外服务。

`Features.developer_screen_priority = 3`声明Android能力，`Misc.screen_access = 42`传递`ScreenAccess(paused, revision, developer_mode)`。已有字段不改类型/编号，旧PC缺省普通；新PC遇旧Android明确提示能力不支持，旧Android不能实施画面优先。完整行为要求两端升级。

## 生命周期与并发

`src/screen_policy.rs`只持有角色/暂停/revision/切换时刻；`developer_mode::android`在单Mutex内更新成员及排队状态事件，锁内不await、不跨JNI、不拿视频锁。视频和ADB生产端过滤，网络出队再按当前资格/入队时刻过滤；暂停连接从视频ACK等待及QoS聚合排除。已进入网络发送的包不能撤回，PC收到策略事件后遮住旧画面并拒收后续帧。

PC解码发布和策略切换共用发布锁，并用generation废弃旧解码回调；ADB队列使用epoch及发布前后检查。恢复重新启用Texture首帧通知，只在真实普通/ADB帧到达后清理恢复提示。暂停不重置录屏选择，不因无操作超时关闭会话。多窗口重放策略快照与网络更新共用锁，避免旧快照覆盖新状态。

未选仅在Flutter隐藏画面（仍会传输）或关闭连接/停止全局采集（影响语音及开发者）。无新线程、定时器、外部服务、依赖或生成桥修改。
